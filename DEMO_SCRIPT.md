# Сценарий демо (1–3 минуты)

Перед записью: откройте терминал в корне репозитория, убедитесь, что есть `artifacts/final_model.joblib`, и соберите/запустите Docker-образ:

```bash
docker build -t wb-sentiment:1.0.0 .
docker run --rm -p 8000:8000 wb-sentiment:1.0.0
```

Оставьте контейнер работать. Во второй вкладке терминала выполните проверки ниже, показывая экран и коротко комментируя происходящее.

## План записи

«Проект классифицирует отзывы Wildberries на положительные, нейтральные и отрицательные. Метки сформированы по оценке товара: 1–2, 3 и 4–5 звёзд соответственно».

**0:20–0:45 — модель и оценка.**

«Сравнивались три варианта TF-IDF с линейными моделями. Разбиение сделано по товарам, чтобы отзывы одного товара не попадали одновременно в обучение и тест. Модель выбрана по macro F1 на валидации; тест использовался после выбора. Итоговый test macro F1 — 0.6276».

**0:45–1:35 — HTTP API.**

Проверка готовности:

```bash
curl -i http://127.0.0.1:8000/health
```

Предсказание:

```bash
curl -i -X POST http://127.0.0.1:8000/predict \
  -H 'Content-Type: application/json' \
  -d '{"text":"Отличное качество, очень нравится!","pros":"удобно","cons":""}'
```

«Сервис возвращает предсказанный класс, версию модели и идентификатор конфигурации модели».

«Пустой отзыв отклоняется с HTTP 422. Это демонстрирует проверку входных данных».

«Код, инструкция запуска, карточки набора данных и модели, результаты экспериментов и ограничения проекта перечислены в репозитории. Версия проекта помечена тегом v1.0.0».
